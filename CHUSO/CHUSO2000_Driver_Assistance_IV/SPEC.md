# CHUSO2000_Driver_Assistance_IV 仕様書

運転支援マイコン。物理センサと `Monitor Status` から現在位置と次の停車駅を求め、タッチ画面で行路（種別・出発駅・行先など）を入力させ、結果を `Drive Support` composite と画面の映像に出す。

ここに書く事実は `main.sw-net` と `scripts/*.lua`、`src/*.lua` から読み取ったものである。設計判断の経緯は `DESIGN_LOG.md` にある。ゲーム内で確かめていない項目には `[unconfirmed]`、コードの配線や名前から推論した項目には `[inferred]` を付ける。

## ポート

| ポート | 方向 | 型 |
|-------|------|----|
| `Monitor Status` | in | composite |
| `Physics Input` | in | composite |
| `Drive Support Monitor Touch` | in | composite |
| `Drive Support` | out | composite |
| `Output` | out | video |
| `Monitor Beep` | out | boolean |

## 構成

| ノード（`main.sw-net` のインスタンス名） | スクリプト | 役割 |
|---------------------------------------|-----------|------|
| `monitor_status_decoder_lua` | `n130.lua` | `Monitor Status` の行路コードと位置情報を、表示用の数値に分解する |
| `route_logic_lua` | `n61.lua` | GPS と距離程から現在の駅を補正し、次の停車駅と接近状態を求める |
| `drive_support_monitor_lua` | `n105.lua` | タッチ入力を処理して、ページ遷移と行路の入力値を出す |
| `drive_support_output_lua` | `n141.lua` | 行路と状態を 1 tick に 1 件ずつの列にして `Drive Support` に出す |
| `drive_support_data_lua` | `n106.lua` | 現在のページに応じた描画コマンドを作る |
| `drive_support_bg_lua` | `n107.lua` | 背景を描く |
| `drive_support_overlay_lua` | `n115.lua` | 前景を描く |
| `drive_support_output_video_lua` | `n127.lua` | 最終映像を出す。ページ 4000 では数値 2 つを重ねる |

`route_logic_lua` は、駅と接近の判定を行う。`main.sw-net` のノード名は、実際のチャンネルの意味に合わせてある（例: `gps_x_read`、`door_open_a_read`、`approach_latch`、`formation_front_selected`）。

### `scripts/` と `src/` と `deploy/` の関係

- `scripts/n61.lua` と `scripts/n141.lua` は、ゲームの XML を取り込む側が書く場所である。手で直さない。
- 手で直すのは `src/n61.lua` と `src/n141.lua` である。路線データは `src/route_data_position.lua` と `src/route_data_arc.lua` にあり、Teinishi 氏のリポジトリの `route_data.json` から `tools/route-data-sync/` が生成する。手で直さない。
- `deploy/n61_deploy.lua` と `deploy/n141_deploy.lua` は、`src/` を縮小したゲーム投入用の生成物である。
- `scripts/` と `deploy/` の違いは、`DESIGN_LOG.md` の記録では `coord_tbl` の 2 番目の座標だけである（`scripts/` は `{303,-4819}`、`src/` は `{158,-4590}`）。`scripts/` への反映は別の作業として扱う。`export` すると、ゲーム内のマイコン（XML）の n61 と n141 は、`src/` からの生成物（`deploy/`）に置き換わるので、`scripts/` のままでよい（利用者の回答）。

## 信号の流れ

以降、`MS Bn` / `MS Nn` は `Monitor Status` の bool / number ch n を指す。

### 有効判定とドア開の判定

- 有効（n61 の B1）: MS N12 が 1 のとき true。`THRESHOLD` の min と max を 1 にして一致を調べている。MS N12 は `SignalComposite.md` では編成向きである。
- 出発確認（n61 の B2）: 有効の立ち上がりの 1 tick パルス。
- ドア開の判定（n61 の B4）: 次の `SR_LATCH` を、立ち上がりも立ち下がりも 0.5 秒の `CAPACITOR` に通したもの。
  - set: MS B12 または MS B13（A 側と B 側の開扉）が true、または有効の立ち上がり。
  - reset: MS B12 と MS B13 がともに false、かつ `Physics Input` ch9 の絶対値が 1.5 以上。
- 接近状態（n61 の B3）: 次の `SR_LATCH` の出力。
  - set: n61 の出力 B4。
  - reset: n61 の出力 B5、またはドア開の判定ラッチの立ち下がり。

### n61 の入力

| 入力 | 元の信号 |
|------|---------|
| N1 | `Physics Input` ch1（GPS X） |
| N2 | `Physics Input` ch3（GPS Y） |
| N3 | 距離程の積分値（後述） |
| N4 | MS N3（行路コード A） |
| B1 | 有効 |
| B2 | 出発確認 |
| B3 | 接近状態 |
| B4 | ドア開の判定 |
| B5 | 未接続のため false |

### 距離程の積分

`pos = pos_prev × f + (Physics Input ch9 / 60) × d + base`

- `d` は MS B16 が true のとき `-1`、false のとき `+1`。
- `f` と `base` は、`n105` の B7 が true のとき `f = 0`、`base = n61 の N32`、false のとき `f = n61 の N31`、`base = n105 の N7` である（`NUM_SWITCHBOX` は `switch` が true のとき `a`、verified）。
- 意図どおりである（利用者の回答）。n61 が「駅直近」と判定し、距離程を更新する意志があるときだけ、距離程を差し替える。n105 の B7 は、その更新の意志（距離程のボタンを押したこと）を表す。
- n61 が補正の値を出していない tick（N32 が 0）に B7 が true になると、`f = 0`、`base = 0` なので、距離程は 0 付近に置かれる。

## n61.lua（駅と接近の判定）

### 出力

出力の ch は次のとおり。

| ch | 内容 |
|----|------|
| N1、N2 | モードが 1 か 3 のとき（停車中にドア開、または接近中）は次の停車駅と、その次の停車駅。それ以外は次の駅と、次の停車駅 |
| N3 | モード |
| N4 | 方向（1 または 2） |
| N9 | 距離程（デバッグ用） |
| N31、N32 | 距離程を更新するとき `0` と `kp`、しないとき `1` と `0` |
| B1 | 有効（そのまま通す） |
| B2 | 出発確認（そのまま通す） |
| B3 | 次の駅がドアカット対象 |
| B4 | 接近状態の set |
| B5 | 接近状態の reset |

モードは次のとおりである。

| 値 | 条件 |
|----|------|
| 0 | 有効でない、行路がない、または次の停車駅がない |
| 1 | ドア開で、次の停車駅までが 520 m 未満 |
| 2 | 次の停車駅がある |
| 3 | 接近状態 |

条件を複数満たすときは、1、3、2 の順に優先する（コードは 2、3、1 の順に上書きする）。方向は、行路が「inb」（探索で `inb = true` が付いたもの）のとき 2、それ以外は 1 である。1 と 2 は、ARC の路線/上下線選択 `b`（1: 北港・掘戸町方面、2: 潮凪浜・南江町方面）と、次の対応になる（verified。[宗弥急行プロジェクト ARC](https://nonasaba.net/sw-train-docs/support/Soya-Express-ARC.html)の仕様と、n141 が `inb` のとき ARC に 10000 を足すコードによる）。

| N4 | 行路の探索 | ARC の `b` | 方面 |
|----|-----------|-----------|------|
| 2 | `inb = true` | 1 | 北港・掘戸町方面 |
| 1 | `inb = false` | 2 | 潮凪浜・南江町方面 |

### 行路探索

- 行路コード A は `(種別 << 12) | (出発駅 << 6) | 行先駅` で、各 6 bit 以下に分ける（種別は 4 bit）。
- コードが変わったとき、`link_tbl` を幅優先で探索して、出発駅から行先駅までの駅の列を作る。2 方向（`inb = true` と `inb = false`）で探索して、短いほうを採る。
- 駅は 16 まで、`coord_tbl`（GPS 座標）、`meterage`（距離程 [m]）、`stop_type_tbl`（駅ごとの停車する種別）が定義されている。最大の距離程は 12320 m である。
- ドアカットの対象は、駅 6、10、14 である。

### 距離程の補正

ドア開（B4）または出発確認（B2）のとき、GPS 座標が 100 未満の距離にある最寄りの駅の距離程を、`kp` とする。さらに、B5 または出発確認が true のとき、N31 に 0、N32 に `kp` を出す。B5 は未接続なので、実際は出発確認が true のときだけである。

### 次の駅と接近

- 方向の符号を掛けた「駅までの距離」を `lts = (meterage − kp) × dir` とする。
- ドア開または接近状態のときは `lts < -300`、それ以外は `lts < 0` を満たす最後の駅を「通過済み」とし、その次の駅が次の駅である。
- 次の駅以降で、行路の始点か終点、または `stop_type_tbl` が種別を含む駅を、次の停車駅、その次の停車駅とする。
- 次の停車駅までが 400 m 以上 520 m 未満なら接近状態を set、520 m を超えたら reset する。

## n130.lua（Monitor Status の分解）

入力は `Monitor Status` である。

| 出力 | 内容 |
|------|------|
| N7 | MS N1 の整数部（行路番号） |
| N8 | MS N2 の整数部（ARC） |
| N9 | MS N3 の種別（`(N3 >> 12) & 15`、最大 11） |
| N10 | MS N3 の出発駅（`(N3 >> 6) & 63`） |
| N11 | MS N3 の行先駅（`N3 & 63`） |
| N12 | 種別。MS N5 が 0 のとき MS N3 の種別、それ以外は MS N5 の種別（最大 11） |
| N13 | 行先駅。MS N5 が 0 のとき MS N3 の行先、それ以外は MS N5 の下位 6 bit |
| N14 | 方向（後述） |
| N15 | 位置情報の種別（`MS N6 >> 12 & 3`。種別が 2 で駅が同じなら 4） |
| N16 | 位置情報の駅（`MS N6 >> 6 & 63`） |

N14 は、MS N6 の `(>> 14) & 3`（`s`）と、ARC を 10000 で割った商から決める。商が 0 でないとき、偶数なら 1、奇数なら 2 を `a` とし、商が 0 なら `a = 0` とする。`s` が 0 なら N14 は `a`、`s` が 0 でなく `a` と違うなら 3、同じなら `s` である。意味は `[unconfirmed]`。

## n105.lua（タッチ UI）

入力は `display_support_composite`（`Drive Support Monitor Touch` に、n130 の出力などを足したもの）である。

| 入力 | 内容 |
|------|------|
| B1、B2 | タッチ 1、タッチ 2 の押下 |
| N3、N4 | タッチ 1 の座標 |
| N5、N6 | タッチ 2 の座標 |
| N32 | 現在のページ |

ボタンの領域は、押した位置が矩形に入ったかで判定する（座標はコード中の `T(x, y, w, h)`）。出力は `N_c = 値`、`B_c = 設定` の組で、`B_c` が立った tick に、対応するメモリレジスタ（後述）へ値が入る。ページの移動は、N32 と B32 の組で行う。

### ページ

| ページ | 内容 |
|-------|------|
| 0 | メインメニュー。3000、100、4000、2000 へ進める |
| 100 | 200 または 1000 へ進める |
| 200、201 | 種別 N1 を選ぶ。200 は 1〜4、201 は 5、6、11、7、8、9。選ぶと 300 へ進む |
| 300〜303 | 出発駅 N2 を選ぶ（1〜16、1 ページに 4 駅）。選ぶと 400 へ進む |
| 400〜403 | 行先駅 N3 を選ぶ（1〜16）。選ぶと 100 へ戻る |
| 1000 | 点呼行路の種別 N4 を 1〜4 から選ぶ。選ぶと N5 を 0 にして 100 へ戻る。右上のボタンは N4 と N5 を 0 にして 100 へ戻る |
| 1001 | 点呼行路の種別 N4 を 5、6、11、7、8 から選ぶ。選ぶと 1100 へ進む。右上のボタンは 1000 と同じ |
| 1100〜1103 | 点呼行路の駅 N5 を選ぶ（1〜16）。選ぶと 100 へ戻る |
| 2000、2001 | メニュー N6 を選ぶ（2000 は 1〜4、2001 は 5〜8）。選ぶと 0 へ戻る |
| 3000 | 3100 へ進める |
| 3100〜3103 | 距離程の値 N7 を選ぶ（-1000、0、300、1635、2925、3500、4190、5570、7810、9030、9220、10000）。選ぶと 3000 へ戻る |
| 4000 | デバッグ。N8 に数字（0〜9）を入力し、1 つのボタンで N9 と N10 を 0 にして 0 へ戻る |

種別や駅の番号が指すものは `[unconfirmed]`。

### メモリレジスタ

`drive_data_1` から `drive_data_6` の `MEMORY_REGISTER` は、n105 の N1〜N6 を、B1〜B6 が立った tick に記憶する。

| レジスタ | 内容 |
|---------|------|
| 1 | 種別 |
| 2 | 出発駅 |
| 3 | 行先駅 |
| 4 | 点呼行路の種別 |
| 5 | 点呼行路の駅 |
| 6 | メニュー |

`destination_code_memory` は、4 桁の行先コードを記憶する。B8 の立ち下がりで、N8 の 1 桁を右に足す（`(x × 10 + y) % 10000`）。B9 の立ち下がりで 0 に戻す。ページ番号は `key_position_memory` に記憶する（B32 の立ち下がりで N32 を記憶する）。

## n141.lua（Drive Support の出力）

入力は `drive_support_num_composite` である。

| 入力 | 内容 |
|------|------|
| N11〜N14 | n61 の出力 N1〜N4（次の駅 1、次の駅 2、モード、方向） |
| B11 | 有効 |
| B12 | 出発確認（未接続のため、実際は常に false。開発が進んでいない機能と考えられる） |
| B13 | ドアカット |
| B14 | MS B16 |
| N1、N2、N3、B3 | 種別、出発駅、行先駅と、これらを更新したこと |
| N4、N5、B5 | 点呼行路の種別、点呼行路の駅と、これらを更新したこと |
| N6、B6 | メニューと、更新したこと |
| N8、B10 | 行先コードと、更新したこと |

出力に積む値は次のとおり。

| 契機 | 値（下位 24 bit） |
|------|------------------|
| 有効で状態が変わった、または出発確認 | `5<<20 \| (方向 & 3)<<14 \| (モード & 3)<<12 \| (次の駅 1 & 63)<<6 \| (次の駅 2 & 63)` |
| B3 が立った | ARC と、行路コード（2 件） |
| B5 が立った | `(点呼種別 & 15)<<12 \| (駅 & 63)` に `4<<20` |
| B10 が立った | 行先コードのまま |
| B6 が立った | `メニュー \| 6<<20` |

ARC は、[宗弥急行プロジェクト ARC](https://nonasaba.net/sw-train-docs/support/Soya-Express-ARC.html)の 7 桁（運行番号 `pp`、路線/上下線 `b`、種別 `tt`、行先 `dd`）のうち、`b tt dd` の 5 桁を作る。`b` は、行路探索の方向で 10000（inb、`b` = 1）または 20000（outb、`b` = 2）、`tt` は種別テーブルから `×100`、`dd` は行先テーブルの値である。行路コードは `2<<20` を付ける。ARC には `1<<20` を付ける。

値は 1 tick に 1 件ずつ出力 N1 に出し、float のビット列として書く。キューが空のときは、センチネル `1<<24` を出す。N2 はキューに残る件数である。

その他の出力は次のとおり。

| 出力 | 内容 |
|------|------|
| B2 | MS B16 でなく、ドアカットがあるとき（ドアカット A） |
| B3 | MS B16 で、ドアカットがあるとき（ドアカット B） |
| B4 | モードが 3（接近中） |

ポートの `Drive Support` には、n141 が書いたチャンネル（N1、N2、B2〜B4）だけが出る。

## 画面

- `n106.lua`: 現在ページと値から、描画コマンドを数値の ch N1〜N30 に出す。1 本のコマンドは、float のビット列に詰めてある。
- `n107.lua`: 背景を描く（地は暗色で塗る）。
- `n115.lua`: 前景の文字を描く。
- `n127.lua`: ページが 4000 のとき、N7 と N17 を、それぞれ 4 桁の数字にして重ねる。

`Monitor Beep` は、n105 の B32（ページ移動）、B8、B9 のどれかが true になる立ち上がりの否定である。通常は true で、立ち上がりの 1 tick だけ false になる `[inferred]`。同じ値が、`drive_support_bool_composite` の B32 にも入るが、n141 を通らないため出力には出ない。
