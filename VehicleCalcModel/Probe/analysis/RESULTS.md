`f' = (K·m(t-d)·(1 − c·b(t-d)) − f) / τ`、`dv/dt = f − k·v − B·b(t-d)·v`

| 記号 | 値 |
|---|---|
| K | 36.69 m/s² / 単位 |
| k | 0.1079 1/s |
| B | 2.108 1/s / 単位 |
| c | 0.947 |
| d | 3 tick |
| τ | 1.43 tick（立ち上がりと立ち下がりで同じ。分けても改善しない） |

当てはめに使っていない 46 本（slip の記録を除く）の最悪の最大誤差は 0.451 m/s、平均 rms は 0.075 m/s。

## むだ時間に含まれるロジック遅延

表の `d`（3 tick。小信号の高周波では約 5.5 tick）は、**プローブの配線のロジック遅延を含んだ**合計である。
ノードは直列でも 1 個ごとに 1 tick 遅れる（verified、利用者の説明）。内訳は次のとおり。

| 区間 | 通るノード | 遅れ |
|---|---|---|
| 出力（プローブ → モーター・ブレーキ） | Composite Read Number 1 個 | 1 tick |
| 入力（物理センサー → プローブ。速度もこれを通る） | Composite Write Number 1 個 | 1 tick |
| Lua ノード自身 | — | 0 または 1 tick（数え方が unconfirmed） |
| 車両そのもの | 上の合計との差 | 下で計算 |

車両単体のむだ時間 = 測った合計 − 配線の合計（2 tick、Lua を数えるなら 3 tick）:

| 測った合計 | 車両単体（Lua を数えない） | 車両単体（Lua を数える） |
|---|---|---|
| 3 tick（階段入力、一次遅れ 1.43 tick を別に持つ） | 1 tick | 0 tick |
| 約 5.5 tick（小信号の高周波、一次遅れなし） | 約 3.5 tick | 約 2.5 tick |

- Momelink の閉ループを評価するときは、この**車両単体の値**を使い、Momelink 自身の配線のロジック遅延を
  別に足す。合計の値をそのまま使うと、プローブの配線ぶんを二重に数える。
- 合計が 3〜5.5 tick と信号の種類で変わる理由は分かっていない（unconfirmed。上の「周波数応答」）。
  車両単体の値も、その幅を持つ。

## ランカーブの再現（慣性補完の模倣）

runcurve-planner（別リポジトリ。読み取りのみ）の運転曲線を、ゲーム内で再現した。
試行は `semi_dn_hokko-takamigaoka_v110`（準急、北港 → 高見が丘、2936 m、前進）で、計画は
0 → 110 km/h（30.6 m/s）まで力行（70 s、1482 m）→ 惰行（2419 m 地点まで）→ 制動（停止用 0.8 m/s²）、
全体で 138.2 s。実機の線路の落下しない範囲（x = -5690 から前進し、-2763 で停止）に収めた。

慣性補完の模倣として、モーターは常に走行抵抗（`k·v`）を相殺するぶんを出し、計画の加速度を足す。
計画の速度を時間の関数 `v_ref(t)` とみなして区間ごとの直線で近似し（16 区間）、速度の追従（ゲイン g = 0.02）を加える。

`モーター = (a_i + k·v)/K + g·(v_ref − v)`

停止の段階は、モーターが負にならないよう、速度が高い間はモーターで `-0.8 m/s²`、低速では減速度一定のブレーキの式
`ブレーキ = 0.8/(B·v) − k/B` に、速度の条件（`vend`）で切り替える。プログラムは 19 区間、1129 文字。

| 項目 | 結果 |
|---|---|
| 速度の誤差（計画の継続時間内） | 最大 0.426 m/s、rms 0.117 m/s。巡航中は 0.08 m/s 以内。最大は停止の最終段階 |
| 停止位置 | 走行距離 2927.0 m（計画 2935.7 m）。8.7 m（0.3%）手前 |
| 停止までの時間 | 139.0 s（計画 138.2 s） |
| 最大モーター入力 | 0.095（slip の境目 0.56 の内側） |
| slip・落下・中断 | なし |

仮の許容誤差 0.5 m/s の内側。計画の速度に対する再現であり、計画そのものの妥当性（宗弥急行の実車の特性）は別の問題である。
スクリプト: `runcurve_plan.py`（計画の軌跡を CSV に）、`runcurve_program.py`（プログラムの生成）、`compare_plan.py`（比較）。
車両特性は、runcurve-planner の車両ファイル（走行抵抗込みの正味加速度）ではなく、
ゲーム内で同定したモデルを使い、計画の加速度をそのまま目標にしている。

## ブレーキ中の走行抵抗の扱い

一定の減速度 1.5 m/s²（25 m/s から 1.2 m/s まで）を、次の 2 通りで出して比べた（run は `data/log.csv` の最後の 2 本）。

- **A（ブレーキのみ）:** モーター 0、`b = a/(B·v) − k/B`。抵抗を「合計の減速度」に数える。
- **B（厳密な相殺）:** `b = a/(B·v)`、モーターで抵抗を打ち消す `m = k·v/(K·(1 − c·b))`。この `m` を `v` の級数
  `m ≈ (k/K)·v + k·c·|a|/(K·B) + k·c²·a²/(K·B²)/v` に展開し、プローブの式の基底（`v`、定数、`1/v`）に収めた。

| 速度 [m/s] | A の減速度 | B の減速度 | 目標 |
|---|---|---|---|
| 24〜20 | 2.37 | 1.42 | 1.50 |
| 20〜15 | 1.87 | 1.41 | 1.50 |
| 15〜10 | 1.43 | 1.40 | 1.50 |
| 10〜5 | 1.41 | 1.40 | 1.50 |
| 5〜2 | 1.41 | 1.39 | 1.50 |

- A は約 14 m/s より速いと `b` が負になり、ブレーキが 0 で頭打ちになる。そのときの減速は抵抗だけ（`k·v` = 2.6 m/s²
  @ 24 m/s）で、目標より大きい。抵抗が目標より強いときは、ブレーキでは弱められない。
- B は全域でほぼ一定（1.39〜1.42 m/s²）で、切り替え（速度条件の区間）が要らない。式の形は複雑にならない。
- どちらも目標より約 7% 弱い。ブレーキが弱い領域（`b` が 0.03〜0.5）では、効きが `B·b·v` の予測より約 7% 低い
  ようである（inferred）。一定減速度 3 m/s² の実験（-4〜-8%）と合う。補正するなら、この領域の `B` を約 7% 小さく見る。

## 指令の定式化（受け持ち加速度から指令へ）

運転曲線の再現（慣性補完の模倣）に使う、加速度から指令を決める式。制約は最小にし、前提として記録する。
モーターで制動することも許す（`a_m` は符号付き）。

| 記号 | 意味 |
|---|---|
| `a_m` | モーターが受け持つ加速度（符号付き。負ならモーターで制動する）[m/s²] |
| `a_b` | ブレーキが受け持つ減速度の大きさ（0 以上）[m/s²] |
| `v` | 車両速度の大きさ [m/s]（後退は \|v\| で扱い、符号は最後に付ける） |
| `o_m`, `o_b` | モーター指令、ブレーキ指令 |

```
o_b = a_b / (B·v)
o_m = (a_m + k·v) / ( K·(1 − c·o_b) )
```

全体の加速度は `a_m − a_b`、走行抵抗 `k·v` は打ち消される（`K`、`k`、`B`、`c` は上のモデルの値）。
`a_m = 0`、`a_b = 0` なら `o_m = k·v/K`、`o_b = 0`（抵抗の相殺だけ）。
`x = c·a_b/(B·v)` が小さい間は、`o_m ≈ (a_m + k·v)/K · (1 + x + x²)` で、プローブの式の基底（`v`、定数、`1/v`）に収まる。

式に入れていない前提:

- 前進中に負のモーターで制動すること（`o_m < 0`、`v > 0`）は測定済み（verified）。`o_m` = -0.05、-0.1、-0.2 を 22 m/s から入れ、
  加速度は予測 `−K·|o_m| − k·v` と 0.01〜0.3 m/s² で一致した（-0.2 で測定 -9.34、予測 -9.68。ほかは 0.1 以内）。0 を越えて後退には入らなかった。
- 約 1.4 m/s より遅い領域では、`o_b` が 1 に飽和し、ブレーキ側の `a_b` は出せない。
- ブレーキが弱い領域（`o_b` が 0.03〜0.5）では、効きが約 7% 低い（`B` を約 1.97 と見ると近づく。inferred）。
- むだ時間 3 tick と一次遅れ 1.43 tick は含まない（フィードフォワード）。
- `o_m` が 0.56 を超えると slip する。

## ランカーブの停止を 1 つの式にした再現（後退方向の鏡像）

同じ計画（`semi_dn_hokko-takamigaoka_v110`）を、-x 方向に鏡像で走らせた（x = -1574 → -4487）。停止の段階は、
上の定式化の 1 つの区間（`a_m = 0`、`a_b = 0.8`、`B` は 1.97）で、速度条件の切り替えをしない。

| 項目 | 前進（速度条件の切り替え） | 後退（1 つの式） |
|---|---|---|
| 速度の誤差（最大 / rms） | 0.426 / 0.117 m/s | 0.508 / 0.240 m/s |
| 停止位置 | 8.7 m 手前 | 22.4 m 手前（0.8%） |
| 停止までの時間（計画 138.2 s） | 139.0 s | 137.7 s |

停止の段階の減速度は、17 m/s 以下で目標 0.80 に 0.5% 以内で合う。26 m/s 以上では 3〜5% 強く効く（0.83〜0.84）。
指令が極端に小さい領域（`o_b` が 0.015 付近）では、ブレーキの効きが約 7% 低いという補正（`B` = 1.97）が過剰で、
実際は `B` が約 2.08 相当（inferred）。最初の 6〜8 秒の余計な減速が、-0.5 m/s の差として残り、22 m の位置の差になった。
巡航中の誤差は前進と同じ（0.09 m/s 以内）。仮の許容誤差 0.5 m/s は、速度の最大誤差が 0.008 m/s 超えた。

同じ式を前進方向（鏡像でない。x = -4487 → -1574）でも走らせた。速度の最大誤差 0.509 m/s、rms 0.240 m/s、停止位置 22.4 m 手前で、
後退（鏡像）と 0.01 m/s、0.1 m 以内で一致した。ずれは鏡像の仮定のためではなく、前進と後退で同じに再現する（verified）。

ブレーキの効き `B` は、指令の大きさで変わるように見える（`o_b` 0.015 で約 2.08、0.1〜0.4 で約 1.96、0.3〜1 で 2.04〜2.2）。
線形な `B·o_b·v` では表せず、これは未解決（unconfirmed）。

## ブレーキの効きの曲線

約 22 m/s から、一定のブレーキ指令を 3 秒保ち、速度の減り方（`ln|v|` の傾き）から `rate = k + B_eff·o_b` を求めた
（`k` = 0.1077 1/s は、同じ条件の指令 0 の惰行。前進と後退を交互に走らせた。測定は `beff.py`）。

| 指令 `o_b` | 抵抗に上乗せされる減速率 [1/s] | `B_eff` |
|---|---|---|
| 0.005、0.0075、0.01 | 0 | **効かない（不感帯）** |
| 0.0125 | 0.0251 | 2.01 |
| 0.015 | 0.0301 | 2.01 |
| 0.0175 | 0.0345 | 1.97 |
| 0.02 | 0.0355 | 1.77 |
| 0.025 | 0.0412 | 1.65 |
| 0.03 | 0.0522 | 1.74 |
| 0.05 | 0.0967 | 1.93 |
| 0.1 | 0.2022 | 2.02 |
| 0.2 | 0.4072 | 2.04 |
| 0.4 | 0.8269 | 2.07 |
| 0.7 | 1.4834 | 2.12 |
| 1.0 | 2.1775 | 2.18 |

- **不感帯:** `o_b` が約 0.011 未満では、ブレーキはまったく効かない（verified。0.01 と 0.0125 の間に境目）。
- **それ以上:** `g(o_b) ≈ 2.00·o_b + 0.18·o_b²` で表せる（`o_b` ≥ 0.012。0.02〜0.05 は 0.005〜0.009 低い）。
  小さい指令の `B_eff` の推定には、約 ±0.004 / `o_b` の不確かさがある（`o_b` = 0.025 で ±0.16）。
- これまでの `B` = 2.108 は、大きい指令（0.3〜1）の記録に引きずられた値。小さい指令の領域（停止の大半）では約 2.0。
- 停止の段階（モーターも入る）での効きは、1.97（`o_b` 0.09〜0.19）〜 約 2.07（`o_b` 0.015、高速）で、ブレーキのみの
  2.02〜2.04 と完全には一致しない。モーターとの同時入力の項（`c`）の影響かもしれない（unconfirmed）。
- 停止の式に直すなら、`B` は約 2.0 とし、`o_b` が 0.012 を下回らないように床を置く（高速の停止の始まりは `o_b` が約 0.015 で、
  不感帯のすぐ上に当たる）。

停止の式の `B` を 1.97 から 2.0 に直した（`runcurve_program.py --stop unified --b-stop 2.0`）。
高速の停止の始まりの `o_b` は約 0.0138 で、不感帯（0.011 未満）の外にある。

| 項目 | 後退（鏡像） | 前進 | 前回（B = 1.97） | 最初の再現（速度条件の切り替え、前進） |

| 速度の最大誤差 | 0.341 m/s | 0.341 m/s | 0.508 m/s | 0.426 m/s |

## 静止中の小さい力（貼り付き）

静止中にごく小さいモーターを出したとき、動き出すかを調べた。測定は 2026-10-18。

| 条件 | 結果 |
|---|---|
| 止まった状態から、モーター ±0.002〜±0.03（ブレーキなし） | 最小の 0.002 から動く。動き出しは 8〜36 tick。加速度は予測 `K·o_m` の約 94〜95%（0.002 で 0.067、予測 0.073）。静止中のモーターの不感帯はない（verified） |
| 止まった状態から、ブレーキ 0.3〜0.8 に小さいモーター（有効な値 `m·(1−b)` が 0.0006〜0.0014） | 予測の `v_eq = K·m·(1−b)/(k + B·b)` と約 10% 以内で動く（verified） |
| ブレーキ 0.7 で速度 0 まで減速して止めた直後に、ブレーキ 0.7 を保ったまま小さいモーターを足す | 予測より動かない。有効な値 0.0009 は実測 ÷ 予測 = 0.19（ほぼ静止）、0.0030 は 0.64、0.0150 は 0.95 |

3 行目は、一定の引き算に見える。有効なモーターの値が約 0.0007〜0.0011（加速度にして約 0.03〜0.04 m/s²）を超えないと、
ブレーキで止めた車両は動かない（inferred）。止めた直後だけ貼り付く履歴の依存で、止まった状態から始めた測定には出ない。
勾配の力が、この閾値を超えるかどうかは、勾配を測らないと分からない。

同時入力のモーターの弱まりは、`b` = 0.5〜1.0 で係数 0.51 / 0.40 / 0.35 / 0.29 / 0.18 / 0.00（`b` = 0.5 / 0.6 / 0.65 / 0.7 / 0.8 / 1.0）で、
`1 − b` に合う。これまでの `c` = 0.947 は `b` ≤ 0.6 の記録から出した値で、`c` ≈ 1.0 のほうが `b` が大きい領域に合う（`b` = 1 でモーターが完全に切れる）。

## 車軸の回転数（RPS、入力 ch22）

RPS を入力に出した版で測った（2026-10-18。記録は `../data/log_mo2000_rps.csv`）。車輪の外周の速度の余りを
`s = 2π·0.5·(RPS − v/(2π·0.5))` [m/s] とする（`v` は車両の速度）。

- RPS の余りは、モーター指令に比例する（5.28 回転/秒 / 単位、すなわち `s` = 16.6 m/s / 単位。モ1800形は 4.98〜5.3、15.65）。
- 駆動の加速度（`加速度 + k·v`）は、`s` の線形な式に従う。傾き約 2.17（`s` = 1.0 で 1.81、3.5 で 7.31、5.0 で 10.8、6.5 で 14.4、8.5 で 18.2、9.0 で 19.7）。
  `K` = 36.8 は、傾き 2.17 × 16.6 に合う（モ1800形は 2.0 × 15.65 = 31）。
- slip の信号が ON になるのは `s` > 約 9.5〜10（モーター 0.58 以上）。そのとき駆動は 5.3 m/s² で一定（`s` = 10〜14 で 5.50、5.32、5.27、5.26）。
  モ1800形は、`s` = 約 6.5 で駆動が約 11.7 に頭打ちになり、`s` = 約 9.5 を超えると 5.0 → 2.1 と下がる。slip の `s` の境目は 2 両でほぼ同じ。
- `s` の応答（指令の階段のあと、最終値の 10% / 50% / 63% / 90% に達する tick）: モ2000形は 4 / 4 / 4 / 6 で、約 4 tick のむだ時間と、
  ほぼ純粋な遅れ（一次遅れの `τ_s` 約 0.9 tick）。モ1800形は 4 / 6 / 8 / 16（`τ_s` 約 5.5 tick。指令の大きさによらず同じ）。
- したがって、2 両の「むだ時間 + 一次遅れ」の違い（モ2000形 3 tick + 1.6 tick、モ1800形 2 tick + 6.6 tick）は、`s` の応答の遅れの違いで、
  駆動は `s` の静的な曲線（`μ(s)`）である。モ2000形で見えた、階段入力と正弦波の「むだ時間 3 tick + 一次遅れ」と「5 tick」の違いは、
  実質の遅れ約 4〜5 tick の見え方の差で、矛盾しない（unconfirmed）。

## 検討した構造（複雑なモデルの試み）

階段入力と正弦波の食い違いを一つのモデルで説明するため、次の構造を試し、いずれも効かなかった。
当てはめは、モデルの全パラメータを再度当てはめ、未使用の記録で比べた。

| 構造 | 結果 |
|---|---|
| 立ち上がりと立ち下がりで別の一次遅れ | 改善なし（1.41 と 1.47 tick で同程度） |
| 駆動の変化率制限（上げ・下げ） | 改善なし（最悪の最大誤差 0.78 m/s） |
| モーターとブレーキで別のむだ時間 | 最良はどちらも 3 tick（または、モーター 4 tick + 一次遅れ 0.4 tick） |
| むだ時間 5 tick（減衰なし） | 周波数応答には合うが、全体が悪化（最悪の最大誤差 0.74 → 2.5 m/s） |
| 立ち上がり 4 tick と立ち下がりで別のむだ時間 | 改善なし（滑らかな入力で保持の規則が歪みを出す） |

結論として、運転と階段入力には「3 tick + 一次遅れ 1.43 tick」の単純なモデル、小信号の高周波には
「むだ時間 5 tick」を、使い分ける。この 2 つは、入力の種類（階段・運転と、振動する小信号）による使い分けで、
一つのモデルにはまとめられていない。

## 周波数応答（小信号の正弦波）

モーターを `0.06 + 0.06·sin(2π f τ)` で 0.2〜8 Hz まで振った（run 102、記録は 1 tick 刻み）。繰り返し（run 104）と振幅 2 倍（run 105）も測った。
測定 ÷ モデル（上のモデル）:

| f [Hz] | 0.2 | 0.5 | 1 | 2 | 3 | 5 | 8 |
|---|---|---|---|---|---|---|---|
| 振幅比 | 1.01 | 1.01 | 1.02 | 1.05 | 1.09 | 1.24 | 1.69 |
| 位相差 [deg]（負は測定が遅れる） | -0.7 | -1.5 | -4.3 | -8.7 | -15.3 | -36 | -70 |

- **再現性と振幅（run 104, 105）:** 同じ掃引（0.06 ± 0.06）を繰り返した run 104 は、run 102 とゲイン比 0.01 以内、
  位相 1° 以内で一致した（5 Hz: 1.241 → 1.250、-36.0° → -35.3°。8 Hz: 1.691 → 1.682、-70.0° → -69.6°）。
  振幅を 2 倍にした掃引（0.12 ± 0.12、1〜8 Hz。run 105）でも同じ傾向で、「3 tick + 一次遅れ」のモデルは
  5 Hz で -36.3°、8 Hz で -95.4° と外れ、「むだ時間 5 tick」のモデルは位相 8° 以内、ゲイン比 0.91〜1.01 で合う。
  したがって、2 Hz 以上でのずれは再現し、振幅を 2 倍にしても変わらない。
- 1 Hz 以下では上のモデルで足りる（位相の差が 5° 以内、ゲインの差が 2% 以内）。
- 2 Hz 以上では、モデルは減衰しすぎ、遅れが足りない。小信号では、**減衰のないむだ時間 5 tick** のモデルが
  8 Hz まで合う（位相の差 7° 以内、ゲイン比 0.89〜1.0）。積分器を除いた応答の等価な遅れは、
  3 Hz 以上で一定の約 5.5〜5.7 tick だった。
- 一方、大きな階段入力（モーター 0.3〜0.4）の運転シナリオには、むだ時間 5 tick のモデルでは最大 1.2〜1.8 m/s
  の誤差が出て、むだ時間 3 tick + 一次遅れ 1.43 tick が合う。入力の大きさで遅れの形が変わるように見える。
  理由は分からない（unconfirmed）。
- 車軸の回転数は今回の測定に含まれていない。駆動力や遅れの形に効いている可能性があり（利用者の指摘）、
  入力の大きさで遅れの形が変わるように見える理由の候補の一つである（unconfirmed）。回転数を入力チャンネルに出せば、
  補助チャンネル（`6,ch1,ch2`）で、マイコンの入れ替えなしに記録できる。
- 使い分け: 低周波（〜1 Hz）と大きな運転では「3 tick + 一次遅れ」、小信号の高周波（2 Hz 以上）の評価では
  「むだ時間 5 tick」を使う。評価の対象（Momelink の閉ループ）の帯域が 1 Hz 以下なら、前者で足りる。

## モデル

モーター入力 m は ±0.4 の範囲に限る（車両の受け付け範囲 ±1 のうち、slip を避ける範囲）。
速度 v [m/s]（後退は \|v\| とモーターの絶対値で扱う）、モーター入力 m（-0.4〜+0.4）、
ブレーキ入力 b（0〜1）に対して、

`dv/dt = K·m(t-d) − k·v − B·b(t-d)·v`

| 記号 | 値 | 意味 |
|---|---|---|
| K | 35.99 m/s² / 単位 | モーター入力あたりの加速度（零速度） |
| k | 0.1070 1/s | 無入力時の減速率。速度に比例する抵抗（時定数 9.3 s） |
| B | 2.086 1/s / 単位 | ブレーキ入力あたりの減速率。減速度は速度に比例する |
| d | 3 tick | 記録の時刻 `t` で見たむだ時間。配線の遅れ（下限 2 tick）を含む |

- 抵抗が速度の 2 次ではなく線形であることは、無入力の減速率が 4.7〜24 m/s で一定
  （0.107 /s）だったことによる。
- ブレーキの減速度が速度に比例することは、減速率が速度によらずブレーキ量に比例した
  ことによる（0.3 / 0.6 / 1 で 0.72 / 1.37 / 2.3 程度 /s）。

### モーターとブレーキの同時入力

同時に入れると、単純な重ね合わせ（`K·m − k·v − B·b·v`）は成り立たない。零速度付近の
加速度は `K·m` に対して、ブレーキ 0.1 で 0.88 倍、0.3 で 0.66 倍、0.6 で 0.36 倍だった。
この比はモーター量（0.1 / 0.2 / 0.3）によらず同じだった（run 78, 80, 82, 84, 86）。
ブレーキがモーターの駆動を弱めているように見えるので、モデルに項を足す。

`dv/dt = K·m(t-d)·(1 − c·b(t-d)) − k·v − B·b(t-d)·v`

| 記号 | 値 | 確度 |
|---|---|---|
| c | 0.92〜1.0（短い記録は 1.0 に近く、長い run 78 は 0.92 に近い） | inferred。5 本の同時入力で、どの c でも最大誤差 0.43 m/s 以下（c = 0.96 で rms 0.06〜0.16 m/s） |

モーターだけ、またはブレーキだけのときは `c` の項は効かないので、これまでの結果は変わらない。
実機でなぜこうなるかは分からない。観測した振る舞いだけを記録する。

## シナリオ（モデルから導いた式で入力を作った測定）

入口の式 `u = c0 + c1·v + c2·v² + ci/max(v, vmin)` に、モデルから導いた係数を入れて測った。
目標と実測の比較:

| シナリオ | 式 | 実測 |
