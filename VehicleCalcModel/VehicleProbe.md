# 車両プローブ

マイコンの HTTP 機能を使い、車両の実値を取得するプローブを述べる。
プローブも通常の Lua ノードの一つとして実装する。HTTP の返信で外部から値を
送り込むこともできる。

HTTP は tick 単位の挙動を保証しない。パルスを送る場合も、開始時刻は
（Lua 内にカウンタを持たない限り）決まらず、長さも別途指示しなければ決まらない。
そのため時間の基準はプローブ内のカウンタに置き、記録する時刻もそのカウンタで
付ける。HTTP は、指示と記録を運ぶ手段として扱う。

プローブの役目は、シミュレータの外側にあるものに限る。マイコン内部のロジックの
検証は `tools/sw-net-sim` で足りるという判断であり、プローブでは再検証しない。

- 実車の入力の実像（センサー値、他の部品が出す信号）
- マイコンの出力に対する車両の応答（[車両モデル](README.md)の材料）
- 抵抗特性など、慣性補完のパラメータの妥当性を確かめる材料
  （[InertiaCompensationCheck.md](InertiaCompensationCheck.md)）

## 運用の前提

実験は人が付かない継続運転で行う。中断後に人が戻してくれることは保証できない。
そのためプローブは、止めるだけでなく、エリアへ戻る手段まで持つ。
外から見えるのは HTTP の記録だけなので、停止中も状態を報告し続ける。

## 入出力（composite）

チャンネル番号は、[ProbeWiring.md](ProbeWiring.md) の結線表で決める。結線表は仮置きで、利用者が確定する。

| 方向 | 内容 |
|---|---|
| 入力 number | 車両速度、座標 x / y / z |
| 入力 bool | 実験 Ready（利用者が実験条件の完成時に送る） |
| 出力 number | モーター入力（負は後退）、ブレーキ入力 |

プローブは出力を飽和させない。Lua の桁あふれを防ぐ ±10^6 の上限だけを持ち、飽和は車両に任せる。車両のモーター入力の受け付け範囲は -1 〜 +1、ブレーキは 0 〜 1 である。±0.4 は slip を避けるための取り決めで、測定を行うツール（`analysis/campaign.mjs` の `--mmax`、既定 0.4。ブレーキは `--bmax`、既定 1）が守る。±0.4 を超える入力は slip が出る領域であり、slip の範囲を測るときだけ明示的に使う。

- 同定する応答は「モーター入力 → 速度」であり、加速度換算はしない。加速度換算は
  別のマイコンの仕事とする。記録するのはプローブが出した入力そのものである。
- 距離は x だけで取る。試験会場の線路が X 軸方向に伸びているためで、この向きの
  知識はツール本体に埋め込まず、パラメータとして受ける。y と z は記録だけする
  （y は勾配の目安）。
- 他のマイコンと指令を奪い合うことはないので、Ready 以外の許可条件は持たない。

## 測定経路の遅延

記録されるむだ時間は、車両の遅れにプローブの配線の遅れが足されたものである。
配線の遅れは、次のノードを通る分である（構成の正本は `Probe/main.sw-net`）。

| 経路 | 通るノード |
|---|---|
| 出力（プローブ → モーター・ブレーキ） | Lua → Composite Read Number（1 個。車両側の部品が composite を直接受け取れないため） |
| 入力（物理センサー → プローブ） | 物理センサー composite → Composite Write Number（ch16, 17 を足す。速度・座標もこれを通る） → Lua |
| Ready | On/Off → Numerical Switch → Composite Write Number → Lua |

- 直列経路のノードも、1 個ごとに 1 tick 遅れる（**verified**、利用者による）。
  `storm-mcl spec` はフィードバックの 1 tick 遅れだけを述べているが、直列も同じと扱う。
- 数え方は次のとおり。Lua ノード自身の分を 1 tick と数えるかは unconfirmed なので、
  Lua を除いたノードだけで下限を数える。
  - 出力側: Composite Read Number の 1 個 → 1 tick
  - 入力側（速度・座標）: Composite Write Number の 1 個 → 1 tick
  - Ready: Numerical Switch + Composite Write Number の 2 個 → 2 tick。速度・座標より 1 tick 遅れて届く
- したがって、配線の遅れの下限は出力側 1 + 入力側 1 = 2 tick である。
  同定したむだ時間には「配線の遅れを含む」と明記し、車両単体の値は、この分を引いて読む。
- 配線の遅れの実測は、最初の実験の記録から行う。
- 記録の時刻 `t` は、Lua が入力を読み出力を決めた tick である。モーター入力を変えた `t` と、
  速度が動き始めた `t` の差が、出力経路と入力経路と車両の遅れの合計になる。

## 状態

| 状態 | 内容 |
|---|---|
| 待機 | パラメータ待ち。出力は 0 |
| 実験 | パターンを出している。長さ（tick）は必須で、時間が来れば自分で待機へ戻る |
| 中断 | 保護条件が成立して止めた状態。理由を保持し、外からの確認（ack）があるまで次の実験を始めない |
| 復帰 | 外からの指示でエリアへ戻っている状態 |
| 続行不能 | y が 1 tick で急に下がった（線路から落ちた）と判定した状態。中断とは別で、何も解除できない。出力はモーター 0・ブレーキ 1 のまま固定され、実験者は実験を止めて利用者を呼ぶ |

有限の長さを必須にするのは、HTTP が途切れてもパターンが走り続けないようにするためである。

## 保護

利用者が渡す「限界」は、線路の実際の限界にわずかな余裕を加えたものである。
プローブの自動中断は、限界の 200 m 手前に置く。したがって実験エリアは、
限界の両端からそれぞれ 200 m 内側であり、エリアの値を別に受け取らない。

| 条件 | 動作 |
|---|---|
| 実験中に Ready が OFF | 中断 |
| x が実験エリア外 | 中断 |
| 速度が上限を超過 | 中断 |

- 中断時はモーター入力を 0 にし、ブレーキを出す。
- 限界・速度上限を受け取っていない間は、パターンを出さない。
- 低速ではブレーキが効きにくく、ブレーキだけでは完全に止まらない可能性がある
  （inferred）。停止距離は最初の実験をやるまで分からないため、最初は低速・低振幅
  から始め、記録から余裕を見直す。

## 復帰

- 復帰中の出力は、外から HTTP で送る指示による。プローブは次の制限を課す。
  - エリアへ近づく向きの動きだけを許し、遠ざかる向きの指示は無視する。
  - 速度上限は、実験時より低い別の値にする。
  - 指示は 1 回ごとに長さ（tick）を持ち、時間が来れば出力 0 へ戻る。
- エリア内に入ったら、自動で待機へ戻る。
- 復帰の制限をプローブが持つのは、誤った指示を送っても復帰操作が事態をさらに
  悪化させないようにするためである。

## 前提と確度

| 項目 | 確度 |
|---|---|
| 出力上限をプローブの記録から検出できる | unconfirmed |
| むだ時間の同定精度の下限は 1 tick（約 16.7 ms） | inferred |
| モーター入力は車両の発揮する力に比例する | unconfirmed（慣性補完で実用上うまくいった経験があるだけ） |
| ブレーキの効きは入力そのままの減速度にならず、速度にも依存する（速度で割ると等減速度が得られた経験による） | unconfirmed |
| モーター入力が負なら実際に後退する | verified（利用者による確認） |
| 低速でブレーキだけでは完全に止まらない | inferred |

比例が崩れていた場合に、同定の誤差になるのか別の非線形として現れるのかを区別する
ため、記録と同定の結果には「入力はモーター入力であり、力ではない」と明記する。
ブレーキの速度依存は、初速を数通り振った実験の記録から当てはめる。補正はプローブに
入れない。

## 最初の車両

中宗2000系のモ2000形（片運転台の電動車）。結線は利用者が行い、NITS などの既存の
制御系を完全にバイパスしてプローブの出力を直接つなぐ。したがって記録される応答は
車両本来のモーターとブレーキの性能であり、既存マイコンの補正や協調は入らない。
このため既存マイコンの仕様はプローブの設計に取り込まない。
（確度: verified。利用者による説明）

## 運用の確定事項

- Ready は実験中 ON のままである。OFF になれば中断する。
- 実験中の速度上限は 200 km/h とする。速度に応じて自動中断距離を縮めてよい
  （高速ほど停止距離が伸びるため、距離は速度から決める余地がある）。
  復帰時の速度上限はプローブの設計に委ねられている。
- これは実機実験である。HTTP の呼び出し頻度などの未確認事項は、実験の中で確かめる。

## 入力の式

実験中にスクリプトを再投入できない（8192 文字制約、利用者が画面の前にいない）ため、
入力の式は事前に持ち、係数だけを HTTP で受ける。各出力（モーター・ブレーキ）について、
同じ一つの形を使う。

`u = clamp(c0 + c1·v + c2·v² + cinv / max(|v|, vmin))`

定数・比例・反比例・2 次を、場合分けなしに表せる。`vmin` は必須で、停止時の
0 除算を避ける。`clamp` は各出力の範囲（モーター ±0.4、ブレーキ 0〜1）に合わせる。
時間パターン（開始 `t` と長さ）はこの式とは別の包絡として `u` に掛ける。
（確度: inferred。これで足りるかは実験で確かめる）

速度の単位は m/s である（利用者の指定）。上限 200 km/h は約 55.6 m/s として
プローブ内に固定する。
