# 汎用プローブのバイトコード仕様（草案）

HTTP で注入したプログラムを、tick ごとに走らせる小さな仮想機械の仕様である。
マイコンを再配置せずに、測定（`../AirBrake/SPEC.md`（まだコミットしていない）の実験）と運用中の制御の双方を差し替えられるようにする。

機能は、車両の測定と制御に必要かどうかだけで決める。Lua ノードの文字数に収まるかは別の問いで、末尾の「実装の大きさ」に分けて書く。

## 配置

| 項目 | 内容 | 確度 |
|---|---|---|
| マイコン | 新しく起こす専用のマイコン。HTTP はこのプローブにだけ付ける | 利用者の方針 |
| 内部状態 | 必要なら、Lua ブロック単品の構成にしてよい | 利用者の許可 |
| 健全性の評価 | 外部が評価し、真偽値の入力 B32（ポート 63）で知らせる。このプローブは自分の健全を判定しない。評価は、現地（ウォッチドッグ）とホスト（HTTP の先）に分ける。「健全入力」の節 | 利用者の決定 |
| 健全でないとき | B32 が OFF の間は、全出力ポートが 0（数値）/OFF（真偽値）になる。既存の制御への切り替えは仕様に含めない。弁が両方閉じるので、ブレーキ圧は保持され、解放も加圧もされない。この結果は受け入れる | 利用者の決定 |

## 実行の単位

1 tick の中の順序は次のとおり。

1. 積まれた操作（`COMMIT` 済み）を、積んだ順に適用する。
2. 入力ポートをサンプルする（B32 を含む）。サンプルは tick の中で一定である。
3. コードがロードされていれば、命令 0 から1回走らせる。ロードされていなければ、何も実行しない（停止）。
4. 完了したら、`PST` の書き込みを出力ポートへ反映し、HB を反転する。打ち切られたら、`PST` の書き込みを捨て、HB を反転せず、打ち切りの回数を 1 増やす。
5. 出力を外へ出す。2 でサンプルした B32 が OFF なら、HB と CUT を除く全出力ポートを 0/OFF にして出す。
6. 記録として、メモリの先頭 `N` 個を、この tick の終わりの値で採る。

- コードがロードされていなければ、停止する。出力ポートには何も書かれない（初期値の 0/OFF のまま）。完了した tick がないので、HB は反転せず、外側のウォッチドッグが遮断する。
- `HALT` か、末尾に達したら、その tick は完了する。
  composite を経由する分の遅れは、配線側の遅れとして別に数える（実測は未了、unconfirmed）。
- 命令数の予算 `B`: 実行した命令を `NOP` と `HALT` を含めて数え、ちょうど `B` 個で完了するプログラムは完了とする。完了する前に `B + 1` 個目が必要になったら、打ち切る。末尾に達することは数えない。
- 打ち切られた tick のメモリは、巻き戻さない。途中まで書き換わった状態が残る。打ち切りの回数が、その兆候として記録に載る。
  次の tick は、また命令 0 から走る。
- `B` は 1〜65535（16 ビットで数える）の範囲で、ホスト側の設定とする。プログラムからは宣言も変更もできない（暴走を止める値を、暴走するプログラムに緩めさせないため）。
  値は未決で、実機で1命令あたりの時間を測り、1 tick に許される処理時間（利用者の見立てでは数百 ms が限度）から決める。
  参考値（開発 PC の Lua 5.3。実機の値ではない）: 1800系のコア（`programs/chuso1800/core_only.asm`。まだコミットしていない）は 1 tick に約 500 命令（487〜514）、平均 0.18 ms/tick、約 2.8 M 命令/秒。`state_sync` で包んだデプロイ形（`main.asm`）は、通常の tick で 982 命令以下、再同期の tick（コアを 2 回走らせる）で最大 1774 命令。
  この速さなら、16 ビットの上限 65535 命令でも約 23 ms で、時間より 16 ビットの数え幅のほうが先に効く。実機が PC の 10 倍遅くても、65535 命令は約 230 ms になる。
- メモリは tick をまたいで保持される。フィルタ、積分、ヒステリシス、遅延線などの状態は、これで持つ。

## 数

- 数は Lua の浮動小数（倍精度）である。整数型は持たない。実装は、保存する値を常に浮動小数にそろえる（整数の桁あふれや整数の 0 除算で、全域性が崩れないようにするため）。ビット演算は内部で整数にし、結果を浮動小数へ戻す。
- 計算する命令の結果は、NaN なら 0、絶対値が 1e30 を超えるなら ±1e30 にそろえる。計算の結果は NaN にも無限大にもならない（保証）。どの入力でも結果が定義される（全域的）。
- ビットの読み替え（`I2F`）と入力の取り込み（`PLD`）は計算ではない。これらが書いた値は、NaN や無限大のビットパターンでも、そのままセルに入る。
- `MOV`、`LD`、`ST`、`CMOV`、`F2I`、`PST` は、値をそのまま運ぶ。NaN や無限大のビットを変えない。これにより、float32 のビットパターンを整数として通す経路（`state_sync` など）が、元のコードと同じ変換で通る。
- 計算する命令（運ぶだけの命令と `F2I` 以外）は、オペランドを読むとき、NaN を 0、±∞ を ±1e30 として読む。比較や `MIN`/`MAX` が NaN の並びの順序で結果を変えず、整数への変換でエラーを出さないため。

## メモリ

- 数値メモリ `M[0..65535]` を 1 枚だけ持つ。メモリのアドレスバス幅は 16 ビットで固定する。
- 番地は `floor` して 65536 で割った余りで解釈する。範囲外の番地という状態は存在しない。
- 先頭の `N` 個（`N` はヘッダーが宣言）は、ホストに見える領域である。ホストがサンプルのたびに `N` 個すべてを読む。
- 初期値は 0。実体は、書かれた番地だけが領域を持つ（疎）。
- 入出力はメモリに割り付けない。ポート命令（次節）が担う。

## ポート

- 入力ポートは composite の読み出し、出力ポートは composite の書き込みである。
- ポート番号 `p` は、数値と真偽値のチャンネルを一続きに数える。

| ポート番号 | 対応するチャンネル |
|---|---|
| 0〜31 | 数値チャンネル 1〜32 |
| 32〜63 | 真偽値チャンネル 1〜32 |

- チャンネルの数（32 ずつ）は unconfirmed。番号は `floor` して `P` = 64 で割った余りで解釈する。
- 真偽値ポートを `PLD` で読むと、`M[d]` に 1（ON）か 0（OFF）が入る。`PST` で書くと、`M[a] > 0` なら ON、そうでなければ OFF になる。`JGZ` と `CMOV` の真偽の見方と同じ規則である。
- 出力ポートは、最後に書かれた値を持ち続ける。初期値は、数値が 0、真偽値が OFF。
- 予約ポートがある。入力のポート 63（B32）は健全入力で、プログラムも `PLD` で読めるが、全出力を 0/OFF にする働きはホスト側が持ち、プログラムからは変えられない。
  出力のポート 62（心拍 HB）と 63（遮断要求 CUT）はホスト層が出す。プログラムの `PST` は、この 2 つには効かない。

## 命令

1 命令は 4 つの数 `op, d, a, b`（フィールド名）。`op` は `floor` して命令の種類数（30）で割った余りで解釈する。
命令番号は追記専用である。コンパイル済みのプログラムが番号に依存するので、既存の番号は変えず、新しい命令は末尾に足す。
使わないフィールドは無視される（アセンブラは 0 を書く）。
ジャンプ先は `floor` してプログラムの命令数で割った余り、ポート番号は `floor` して 64 で割った余りで解釈する。
どの数の並びも、有効な命令として解釈できる。不正な命令という状態は存在しない。

表の `d`、`a`、`b` は、そのままフィールドの名前である。「番地」とある場合、フィールドの値は番地そのもので、`M[フィールド]` を読み書きする。

| 番号 | 命令 | 動作 |
|---|---|---|
| 0 | `NOP` | 何もしない |
| 1 | `MOV d a` | `M[d] ← M[a]` |
| 2 | `ADD d a b` | `M[d] ← M[a] + M[b]` |
| 3 | `SUB d a b` | `M[d] ← M[a] − M[b]` |
| 4 | `MUL d a b` | `M[d] ← M[a]·M[b]` |
| 5 | `DIV d a b` | `M[d] ← M[a] / M[b]`。`M[b] = 0` のときは 0 |
| 6 | `MIN d a b` | 小さい方 |
| 7 | `MAX d a b` | 大きい方 |
| 8 | `ABS d a` | 絶対値 |
| 9 | `FLR d a` | 床関数 |
| 10 | `SQRT d a` | 平方根。負のときは 0 |
| 11 | `SIN d a` | `sin(M[a])`（ラジアン）。試験信号の生成に使う |
| 12 | `CLP d a b` | `M[d] ← clamp(M[d], M[a], M[b])`。`M[a] > M[b]` のときは `M[b]` |
| 13 | `LT d a b` | `M[a] < M[b]` なら 1、でなければ 0 |
| 14 | `LE d a b` | `M[a] ≤ M[b]` なら 1、でなければ 0 |
| 15 | `CMOV d a b` | `M[b] > 0` なら `M[d] ← M[a]`。でなければ変えない |
| 16 | `LD d a` | `M[d] ← M[ floor(M[a]) mod 65536 ]`（間接読み出し） |
| 17 | `ST d a` | `M[ floor(M[d]) mod 65536 ] ← M[a]`（間接書き込み） |
| 18 | `PLD d a` | `M[d] ←` 入力ポート `a` の、この tick の初めにサンプルした値（`a` は即値のポート番号） |
| 19 | `PST d a` | 出力ポート `d` へ `M[a]` を書く（`d` は即値のポート番号、`a` は番地）。tick が完了したときに外へ出る |
| 20 | `JMP a` | 命令 `a` へ（`a` は即値の命令番号） |
| 21 | `JGZ a b` | `M[b] > 0` なら命令 `a` へ（`a` は即値の命令番号、`b` は条件の番地） |
| 22 | `HALT` | この tick を終える |
| 23 | `F2I d a` | `M[a]` を float32 に丸めたときのビットパターンを、符号なし 32 ビット整数として `M[d]` に入れる |
| 24 | `I2F d a` | `M[a]` を符号なし 32 ビット整数とみなし、そのビットを float32 として `M[d]` に入れる。結果が NaN や無限大のビットパターンでも、そのまま入る |
| 25 | `AND d a b` | 符号なし 32 ビットの論理積。オペランドは `floor` して 2^32 で割った余りで解釈する |
| 26 | `OR d a b` | 論理和（同上） |
| 27 | `XOR d a b` | 排他的論理和（同上） |
| 28 | `SHL d a b` | `M[a]` を `M[b]`（`floor` して 32 で割った余り）ビット左へ論理シフト。結果は 2^32 で割った余り |
| 29 | `SHR d a b` | 右へ論理シフト（同上） |

アセンブラは、オペランドを表の記載順に、そのフィールドへ入れる（`PST 0, x` なら `d` = 0、`a` = `x` の番地）。

演算の命令は、すべてメモリの番地をオペランドにとる。即値の演算命令（`ADDI` など）は持たない。ポート番号 `p` とジャンプ先 `a` だけが、命令の形として即値である。定数は、下の「アセンブラ」の定数プールで扱う。

後ろ向きのジャンプも許す。暴走は、命令数の予算が止める。
`LD`、`ST` は、格子表の引き当て（同定した流量写像など）、遅延線（弁指令の遅れ）、折れ線の軌道表に使う。

## 注入

コード（プログラムメモリ）と数値メモリ `M` は、別の領域である。コードは `M` の外にあり、命令からは読み書きできない（自己書き換えは存在しない）。

ホストからの操作は 3 種類である。

| 操作 | 内容 |
|---|---|
| `CODE` | コードを置く。ヘッダーの `N`、命令数も運ぶ |
| `MEM` | `(番地, 値)` の並びをメモリへ書く。動作中でも使える |
| `RESET` | メモリを全部 0 に戻す |

- 3 つとも、まず待機領域に積む。`COMMIT` を受けたら、次の tick の境目に、積んだ順にまとめて適用する。部分的に適用された状態は外から見えない。
- `RESET` を積むかどうかは、ホストが決める。既定は積まない。
- 「新しいプログラムを載せる」は `RESET`、`CODE`、`MEM`、`COMMIT` の並び、「係数だけを変える」は `MEM`、`COMMIT` だけである。
- `CODE` だけを入れ替えても、メモリは消えない。状態を引き継いでロジックだけ差し替えるときに使う。
- 各メッセージに検査和を付ける。合わなければ、積んだものごと捨て、動いているものを変えない。
- 大きいメッセージは、複数回に分けて積んでよい。`COMMIT` までは適用されない。
- 形式は「通信の形式」の節。
- ホストへ HTTP で送るデータは、メモリの先頭から `N` 個だけである。`N` は `CODE` のヘッダーで決まり、コードを入れ替えるたびに変えられる。内部の途中値を見たいときは、プログラムが先頭 `N` 個へ写す。任意の番地の読み出し要求は設けない。
- 動いているコードの検査和を、記録と一緒にサーバーへ返す。意図したプログラムが載っているかを外から確かめる。
- HTTP の応答の大きさ、呼び出しの頻度の制約は未確認（unconfirmed）。分割の大きさは、測ってから決める。
- 再起動でコードとメモリが残るかは未確認（unconfirmed）。残らないなら、起動直後は「プログラムなし」で、全出力は初期値（0/OFF）のままになる。

## 通信の形式

メッセージは 1 行の文字列で、`種別:ペイロード*検査和` の形をとる。ペイロードは 10 進数のカンマ区切りである。
数の書き方は、ホストが決める（倍精度で往復できる桁数を使う）。受ける側は、Lua の `tonumber` で読む。

| 種別 | ペイロード | 内容 |
|---|---|---|
| `C` | `N,off,w1,w2,…` | コードの語（4 語で 1 命令）を `off` 番目から積む。`off` は、積まれているコードの語数と同じか、0（最初から積み直す）でなければならない。`N` は先頭の記録の個数で、最後の `C` の値を採る |
| `M` | `addr,val,addr,val,…` | メモリへ書く `(番地, 値)` の組。番地は `floor` して 65536 で割った余りで解釈する |
| `R` | （空） | メモリを全部 0 に戻す |
| `K` | （空） | `COMMIT`。積まれた操作を、次の tick の境目に適用する |

- 検査和は、`*` より前のバイト列（種別、`:`、ペイロード）について、Adler-32 と同じ式で作る。`a` = 1、`b` = 0 から始め、各バイトで `a ← (a + バイト) mod 65521`、`b ← (b + a) mod 65521`。検査和は `b·65536 + a` の 10 進数。整数だけの演算で、Lua と JavaScript の違い（負の数の `%`）を踏まない。
- 結果は `OK` か、エラーコードである。`E1` は検査和の不一致、`E2` は形式の誤り（語数が 4 の倍数でない、`off` が合わない、組が奇数個、など）。エラーのとき、積まれた操作はすべて捨てる。
- 経路: マイコンの Lua が `http.get` でホストへ問い合わせ、その応答（`httpReply`）の本文に載った行を、1 行ずつ `gp_msg` に渡す。ホストからマイコンへ押し込む経路はない。
  `httpReply` は tick の合間に呼ばれるので、積んだ操作は次の tick の始めに適用される。
  マイコンは同期して返事を返せないので、各メッセージの結果は、次の問い合わせの要求（URL）に載せてホストへ知らせる。記録（先頭 `N` 個）、打ち切りの回数、動いているコードの検査和も、同じ要求に載せる。
  要求の長さと応答の長さの制約は未確認（unconfirmed）。
- 検査和の試験ベクトル（Lua と Node の両方のテストが持つ）:

| 対象のバイト列 | 検査和 |
|---|---|
| `K:` | 13762694 |
| `R:` | 14680205 |
| `M:0,1` | 59179285 |
| `C:8,0,22,0,0,0` | 357040822 |

## アセンブラ（PC 側）

アセンブラは、人が読む形をバイトコードと `MEM` に変換する。仮想機械には、アセンブラの便宜を持ち込まない。

- 定数のリテラル（例: `#0.05`）をオペランドに書くと、`N` 以上の番地に定数のセルを確保し、命令の番地に置き換える。同じ値は 1 つにまとめる。
- 定数のセルの初期値は、`MEM` として出力する。命令数は増えない。
- 定数のセルは書き換え可能なメモリである。ホストが `MEM` で係数を調整できる。プログラムが書き換えないことは、アセンブラが書き込み先のオペランドにリテラルを書く誤りを拒否することで守る（間接書き込みの `ST` は検出できない）。
- 書き方は `tools/gpasm.mjs` が正本である。ディレクティブは `.host N`（先頭 `N` 個をホストに見せる）、`.pub name`（ホストに見える領域のセル）、`.var name [初期値]`（プログラムだけが使うセル）、`.def name 値`（名前の別名）、`.mem 名前または番地 値`。ラベルは `name:`、コメントは `;`。`N1`〜`N32` は数値ポート 0〜31、`B1`〜`B32` は真偽値ポート 32〜63 の別名である。
- 試験用のプログラムは `programs/` に置く。

## 健全性

健全性は外部が評価する。このプローブは自分の健全を判定しない。評価は、見るものによって二つに分ける。

| 見る側 | 見るもの | 手段 |
|---|---|---|
| 現地（車両の中） | ホスト層が動いているか（tick が予算内で完了し続けているか） | 心拍。外側のウォッチドッグが途絶を見て遮断を判定する |
| ホスト（HTTP の先） | 載っているコードの検査和、打ち切りの回数、記録の欠落、実験の限界（`P_BC` の上限、`P_MR` の下限など） | サーバーが記録を読んで評価し、遮断要求を HTTP で出す |

### 出力（ホスト層が出す）

| ポート | 内容 |
|---|---|
| 出力 62（HB） | 心拍。tick が予算内で完了するたびに反転する。打ち切られた tick では反転しない |
| 出力 63（CUT） | 遮断要求。ホストが HTTP で立てる。既定は OFF（要求しない）。ホストが居なくなっても変わらない |

HB と CUT はプログラムから書けない。CUT が既定で OFF なのは、HTTP を使わない運用でも車両が止まらないようにするためである。

### 入力 B32（ポート 63）

B32 が ON の間だけ、出力ポートの値が外へ出る。

- B32 が OFF の間は、ホスト側が全出力ポートを 0/OFF にする。プログラムは動き続けてよい（状態を保つ）が、その出力は外へ出ない。HB と CUT は B32 に関わらず出る。
- B32 が ON に戻ると、出力ポートが最後に書かれた値から再び外へ出る。

### 推奨の配線（仕様の外）

外側で、通常のウォッチドッグ回路（HB の反転が一定の tick 途絶えたら OFF）の出力と、`CUT でない` の論理積を作り、B32 に入れる。
タイムアウトの tick 数はこのプローブの外で決める。composite を経由する遅れを見込んで数 tick の余裕を持たせるのが無難だが、値は未測定（unconfirmed）。

## ホスト側の機能

プログラムが書き換わっても壊れてはならないものは、仮想機械の外に置く。

| 機能 | 内容 |
|---|---|
| 記録バッファ | 毎 tick、メモリの先頭 `N` 個を記録し、まとめて HTTP で送る。間隔はサーバーが指定する。時間の基準はプローブ内の tick カウンタ |
| ガード | 出力ポートごとの範囲の表。出力は範囲に収める。プログラムからは書き換えられない |
| 開始・停止 | 指定した tick から始め、指定した条件で止める。開始前の出力は待機値 |
| 区間番号 | 先頭 `N` 個のうち 1 つを、プログラムが書く区間番号として記録する。解析側は、番号で記録を区切る |

実験の信号（階段、ランプ、正弦波、折れ線）は、PC 側のコンパイラが既存の区間表の形からバイトコードへ変換する。仮想機械には、信号発生器を埋め込まない。

## 確認テスト（実装前に計画したもの）

| 確認 | 内容 |
|---|---|
| 全域性 | 乱択の数列（範囲外・負・小数・巨大値を含む）を、プログラムとして与えても、エラーにならず予算の内で終わる |
| 演算の定義 | 0 除算、NaN、桁あふれ、`SQRT` の負、`CLP` の逆順、`LD`/`ST` の範囲外の番地（65536 での折り返し）の結果が、上の表どおり |
| 予算 | 無限ループのプログラムが、予算で打ち切られ、その tick の出力ポートへの書き込みが捨てられ、出力が直前の値のままになり、打ち切りの回数が 1 増える。次の tick で、プログラムが予算内に戻れば通常に動く |
| ポート | `PLD` が tick の初めにサンプルした値を返す（tick の中で入力が変わっても同じ）。`PST` が tick の完了時にだけ出力に反映される。書かれないポートが最後の値を保つ。範囲外のポート番号が折り返す。真偽値ポートの読み書き（読みは 1/0、書きは `M[a] > 0`）が上の規則どおり |
| ビット演算 | `F2I`/`I2F` の往復が、`lib/state_sync.lua` の `f2i(i2f(n))` と、NaN、無限大、非正規化数を含む代表的なビットパターンで一致する。`MOV`/`LD`/`ST`/`CMOV` を経由しても変わらない。NaN を番地やシフト量に使ってもエラーにならない。`AND`/`OR`/`XOR`/`SHL`/`SHR` が 0、2^32−1、範囲外の入力で表どおり。1800系 Lua Core の `get_bit`/`put_bit` と同じ結果になる |
| 状態の保持 | 低域通過、傾きの制限、ヒステリシス、遅延線のプログラムが、PC 側の参照実装と tick ごとに一致する |
| 疎なメモリ | 散らばった番地へ書いても、書いた番地の分しか領域を使わない |
| 注入 | 検査和が合わない・`COMMIT` 前の途中までのものは適用されず、動いているものが変わらない。`MEM` だけの `COMMIT` で、コードとほかの番地が変わらない。`CODE` だけの `COMMIT` で、メモリが変わらない。`RESET` でメモリが 0 に戻る |
| ガード | プログラムが範囲外の出力を作っても出力は範囲に収まる。範囲が設定されたポートでは、NaN を 0 として範囲に収める。範囲のないポートでは、値をそのまま出す |
| 健全入力 | B32 が OFF の間、全出力が 0/OFF になる（プログラムが動いていても）。HB と CUT は出続ける。ON に戻ると、最後に書かれた値が外へ出る。プログラムは B32 を読めるが、この働きを変えられない |
| 未ロード | コードがロードされていないとき、命令が実行されず、出力ポートが初期値（0/OFF）のまま、HB が反転しない |
| 心拍 | 予算内で完了した tick ごとに HB が反転する。打ち切られた tick では反転しない。プログラムの `PST` は HB と CUT に効かない |
| 遮断要求 | CUT の既定は OFF。ホストの操作で ON になり、操作で OFF に戻る。HTTP が途絶えても変わらない |
| 同一性 | ゲーム内に載せるインタープリターと同じ Lua を、PC のテストでも走らせる |

## 実装の大きさ（別の問い）

Lua ノードの `script` は 8192 文字（ASCII）が上限である。リポジトリのビルド（`tools/microcontroller/lua-build.mjs`）は、`storm-lua-minify` の出力の文字数がこの上限を超えると失敗する。

### 実測（2026-10-19）

入口（`src/gp.lua`: composite の入出力と HTTP の問い合わせ）と仮想機械（`src/gp_core.lua`）を、リポジトリのビルドと同じ設定で minify した文字数。

| 対象 | 文字数 |
|---|---|
| 入口 + 仮想機械（現在の実装） | 5641 |
| うち仮想機械（`dofile` のみの入口で測定） | 5130 |
| うち命令を実行するループ（`run`） | 約 2050 |
| うち入口 | 約 510 |
| 上限までの余裕 | 2551 |

現在の実装は、仕様の「ホスト側の機能」を一部しか持たない。未実装の分は次のとおりで、合計で 700〜1000 文字と見積もる（inferred。書いて測るまで確定しない）。

- 記録バッファ（毎 tick の記録をまとめて送る）。
- 開始・停止、区間番号。
- ガードと遮断要求 CUT、予算 `B` を、通信で設定するメッセージ。

見積もりのとおりなら、6.3k〜6.7k 文字で、上限に収まる。

### 収める指針

余裕が足りなくなったときは、機能を削る前に、次の順で試す。

1. **補助の整理（100〜500 文字）**: デバッグ用の API（`gp_instr`）と、テストだけが使う公開名を外す。`run` の中で繰り返す `nz(M[x] or 0)` を、1 つの局所関数にまとめる（約 400 文字の削減を見込む）。グローバル名の短縮（`gp_` を 1〜2 文字に）は、約 100 文字で効きが小さい。
2. **構造の分割（機能を保ったまま）**: 仮想機械（`gp_tick` と `run`）と、通信・記録・ステージング（`gp_msg` 側）を別の Lua ノードに分ける。二つのノードの間は composite で受け渡す（コミット済みのコードとメモリへの書き込みを、数値の列として流す）。1 ノードあたり約 3k〜4k 文字になる。
3. **並びの検討**: 1 と 2 でも収まらないときに限り、命令の取捨を検討する。ただし機能は必要性で決める（文字数では決めない）ので、その場合は利用者に諮る。

指針 2 の分割は、メモリ `M` がどちらのノードにあるかで設計が変わる。ホストへ送る先頭 `N` 個は、仮想機械側のノードから composite で出す必要がある。分割に踏み切るときに設計する。
