# VehicleCalcModel

様々な車両を同じ手順でモデル化するための共通基盤を置くディレクトリである。
一両のモデルを作ることは目的ではない。

このファイルは車両モデルの基盤だけを述べる。Momelink とは独立であり、
Momelink の安定性評価はこのモデルの利用先の一つとして
[MomelinkStability.md](MomelinkStability.md) が述べる。

## 目的

車両の入力（加速度換算の指令）から速度までの応答を、単純なモデルで表す。
モデルは単純なほどよい。むだ時間を持つ低次の遅れ系を第一候補とするが、
形はまだ確定していない（後述の「未決」）。

## 現在の目標（モ2000 の同定）

モ2000 形の開ループ応答「モーター入力 → 速度」「ブレーキ入力 → 速度」を、速度域
±35 m/s で同定し、モデルと成り立つ範囲を記録に残す。この速度域は暫定で（これは同定の範囲であり、実験の速度を制限する値ではない）、利用先
（[MomelinkStability.md](MomelinkStability.md)）が必要とする速度域が決まったら見直す。

- 求めるもの: むだ時間、入力あたりの加速度（ゲイン）、速度依存の抵抗。
- 合格の見方: 同定に使っていない条件（別の入力量・初速）の記録を、モデルが再現できるか。
  許容誤差は、最初の同定結果を見てから決める。決めるまでは未決として残す。
- 測定と解析の手順: [MeasurementProcedure.md](MeasurementProcedure.md)。測定は [Probe](Probe/SPEC.md) で行い、解析は `Probe/analysis/` に置く。
  結果と、どの記録から求めたかは `Probe/analysis/RESULTS.md` に残す。
- 現状: 速度、モーター、ブレーキの範囲を測り、線形モデルが未使用の記録を最大 0.36 m/s で
  再現した。slip の影響は未確認である（`RESULTS.md`）。

## 次の目標（離席中の自律運転）

モ2000 のモデルを、普通の電車運転（力行 → 惰行 → ブレーキ → 停止、前進・後退、方向転換）と、
正弦波入力（数 Hz まで）で検証し、成り立つ範囲を `Probe/analysis/RESULTS.md` に残す。

- 合格の見方: 同定に使っていない運転シナリオの速度を、仮の許容誤差 0.5 m/s 以内で再現できるか。
  この値は、これまでの最大誤差（0.43 m/s）を参考にした仮置きであり、決定ではない。
- 周波数応答: モデル（一次遅れ + むだ時間 3 tick）が高い周波数まで成り立つかの確認。
  外れる周波数があれば、その周波数と形を記録する。
- 完了または続行不能のときは Discord に通知する。

## 共通のモデルと当てはめの手順

モ2000形とモ1800形は、同じモデル（車輪の回転速度と車体速度の差 `s` を状態にしたもの）と、同じ段階的な当てはめの手順（`Probe/analysis/axle2.mjs`）で、
同程度の誤差（検証の平均 rms が 0.15 と 0.17 m/s、最大誤差が 0.39 と 0.38 m/s）にモデル化できた。
モデル、手順、パラメータ、検証の表は [Probe/analysis/COMMON_MODEL.md](Probe/analysis/COMMON_MODEL.md)。

## 連結した 2 両の同定

連結した 2 両のフォワードモデル（指令 → 列車の平均の速度）は、単両の同定が済んだ 2 台から、固定の実験表（19 本、測定約 25 分）で決める。
モ2000形 + ク2100形、モ1800形 + ク2100形の 2 組で通した。手順は全自動で、人や LLM が決める箇所を持たない。実験、判定、追実験の経緯は [Probe/analysis/PAIR_FIT_PLAN.md](Probe/analysis/PAIR_FIT_PLAN.md)、
モデルと誤差は [Probe/analysis/TWO_CAR_MODEL.md](Probe/analysis/TWO_CAR_MODEL.md)。

## 共通基盤の切り分け

- **共通にするもの**: 測る → 記録する → モデルに当てはめる → モデルが成り立つ範囲を
  述べる、という手順と、その結果の読み方。
- **車両ごとに変わるもの**: パラメータと、モデルの有効範囲。これらの正本は
  車両側に置き、基盤の側には埋め込まない。
- モデルが成り立つ範囲（速度域など）は結果の一部として残す。書かないと、別の
  速度域や別の車両へ黙って流用される。
- 測定の前提: 時間の基準はプローブ内のカウンタに置く。HTTP は tick 単位の挙動を
  保証しないため、むだ時間の同定はこの基準で決まる精度に限られる。
  プローブ自体は [VehicleProbe.md](VehicleProbe.md) が述べる。

## データの扱い

`Probe/data/` のうちコミットするのは、再現に必要な次のものだけである。

- モデルのパラメータ: `params_<車両>.json`、`params_<車両>_freq.json`、組のパラメータ `params_pair_<A>_<B>.json`
- 測定の範囲: `vehicles/<車両>.json`
- 組の設定のサンプル: `pair_config.example.json`（`pair_config.json` にコピーして使う。実物はコミットしない）

同定の作業中に生まれるデータ（測定ログ `log*.csv`、走行コマンド列、実験の記録 `archive_*`・`scenarios`・`twocar*`・`vvvf`・`discarded`、実験表、`pair_fit_result.json`、`pair_config.json` の実物）は、コミットしない。
同定が済んだ結果は、パラメータとして取り出して残す。

測定ログの一部（`*.csv`、`commands.json`、`*.out`）は `.gitignore` で除外している。残りは `.gitignore` に入れていないので、`git status` に未追跡として出る。今後、除外する可能性がある。

組のパラメータは、`pair_fit_result.json`（`pair_loop.mjs` の出力）の `theta` と `chosenForm` を取り出して作る。
単両には、この書き戻しを行う `promote_single.mjs` があるが、組には道具がなく、手作業で作っている。これは正本から作れていない欠陥である。

## 前提と確度

| 項目 | 確度 |
|---|---|
| 速度の2次関数は、車両の抵抗の妥当な近似である | inferred（設計者の見解。裏付けは乏しい） |
| 車両の実際の抵抗が厳密に速度の2次関数である | unconfirmed（設計者の見解では、おそらく正しくない） |
| 抵抗が速度に対して非線形なら、動作点まわりで線形化したときの速度の時定数は動作点の速度に依存し、一つの2次遅れでは速度域全体を表せない | inferred（2次でなくても非線形であれば成り立つ） |

## 未決

- モデルの形。動作点ごとの線形モデルにするか、非線形の式を持つか。
  利用先が何で評価するか（極の位置か、時間応答か）で決まる。
- モデルを当てはめる速度域。
- 進め方。基盤の形は、一両を実際にモデル化しないと見えにくい。最初の一両は
  基盤の検証用として扱い、その一両専用の知識を基盤へ入れない。
